# API 设计审核清单

> 被 `SKILL.md` 步骤3引用：审核对象为 REST/gRPC/GraphQL 接口设计、OpenAPI/Proto 变更时读取本文件。

## 检查项

- **语义规范**：REST 资源命名/HTTP 方法/状态码是否符合规范；gRPC 方法划分是否合理；操作是否幂等（重试安全）
- **版本策略**：版本承载方式是否明确（URL/header）；破坏性变更如何发布；旧版本兼容期与下线计划
- **错误处理**：错误码是否统一、有文档；错误信息是否可操作（不泄露内部细节）；重试/幂等键约定
- **客户端行为映射**：每个错误码对应的客户端动作（重试/降级/提示/登出）是否明确；未定义动作的错误码 ⇒ ⚠️
- **容量与时限**：单请求超时、重试预算、限流阈值、配额单位与超限语义是否写明；分页默认值与上限
- **横切面**：限流/鉴权/审计/分页/过滤/排序/字段裁剪（sparse fieldsets）是否考虑；文档是否可从代码生成
- **兼容性**：新增字段是否可选；枚举新增值客户端能否容忍；序列化格式变更（JSON/Proto）是否双写过渡
- **契约测试**：是否有消费者驱动契约或 schema 校验；破坏性变更能否在 CI 拦截

## 移动端专项（涉及推送/深链/错误码映射时）

**触发判断**：API 设计含以下关键词时自动读取 `mobile-delta.md` 对应节：
- 推送 payload 结构、FCM/APNs 字段差异、data vs notification message
- 深度链接参数、Universal Links/App Links 参数透传、回退 Scheme
- 错误码映射、平台特定错误（网络/权限/后台限制）的统一码

读取 `mobile-delta.md` 的「架构层差异」（推送/深度链接）+「原生稳定性差异」（错误码映射隐含），其余共性项沿用本清单。
