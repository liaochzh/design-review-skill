# 代码实现方案审核清单

> 被 `SKILL.md` 步骤3引用：审核对象为**实施前**的重构计划、新增功能实现方案时读取本文件。
>
> **边界（重要）**：本清单只审「尚未落地的代码实现方案/重构计划」。已提交或工作区中的**真实代码 diff 不在这里审**——请改用 `review` 子代理（它负责对真实改动做正确性/回归/测试遗漏审查）。同一对象不要两种都用。

## 检查项

- **代码模式一致性**：是否遵循团队现有代码模式/命名/分层；新引入的抽象在别处有无先例
- **抽象适度性**：是否引入不必要的抽象或过度设计（YAGNI）；是否为"未来可能"支付了当下复杂度
- **封装与依赖**：是否破坏现有模块的封装；是否新增了跨层/循环依赖；对外暴露的 API 面是否最小
- **向后兼容与迁移**：是否考虑向后兼容；数据迁移/配置迁移路径是否明确；是否支持灰度与回滚
- **可测试性**：新增逻辑是否可单测；是否需要为测试预留 seams（接口/依赖注入）；测试覆盖计划是否具体
- **变更 blast radius**：方案触及的调用方有哪些；是否有"顺手重构"混入无关改动
- **有意变更 vs 违规**：偏离既有代码模式时，区分"未解释的偏离"与"有理由的改造"；后者审理由与迁移成本，不因"与现状不同"直接扣分
- **落地步骤可执行性**：方案若含实施顺序，按 `plan.md` 核对落点精度、顺序依赖、验收命令与占位符残留

## 移动端专项（涉及原生层时）

**触发判断**：方案文本/代码含以下关键词时自动读取 `mobile-delta.md` 对应节：
- 架构层：推送、通信边界、热更新、后台、环境映射、崩溃、深度链接、深链
- 代码层：权限、签名、分包、最低版本、生物识别、Keychain、Keystore、内更、强更

读取 `mobile-delta.md` 的「代码层差异」+「原生稳定性差异」节，其余共性项沿用本清单。
